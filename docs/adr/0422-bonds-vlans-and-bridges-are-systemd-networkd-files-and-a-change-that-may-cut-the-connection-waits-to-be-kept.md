# ADR-0422: Bonds, VLANs and bridges are systemd-networkd files that UNOS writes, and a change that may cut the connection waits to be kept

## Context

`system.network-bonding-and-vlans` asks for bonds (LACP or balance-rr), VLANs on an interface or a bond, and bridges for containers, made and removed in the web UI. A wrong network change cuts the administrator off, and the owner asked "above all that it be safe" (ADR-0013). The host keeps its network in its own configuration: the dev device runs Armbian's minimal image, where netplan renders one systemd-networkd file that matches every `e*` card (`systemd-networkd` is among the services of ADR-0288; PROGRESS.md's IPv6 filter starts before it); Ubuntu Server also renders netplan for systemd-networkd; Raspberry Pi OS, desktops and Armbian's standard images run NetworkManager; Debian's own server install keeps `/etc/network/interfaces` (ifupdown).

## Decision

**Where.** UNOS makes bonds, VLANs and bridges only where systemd-networkd keeps the host's network and NetworkManager does not run (`systemctl is-active` of `NetworkManager.service`, `systemd-networkd.service`, `networking.service`): elsewhere `GET /network/virtual-interfaces` answers `supported: false` with the manager it found, and every change 409. NetworkManager and ifupdown hosts are left open: their own tools (nmcli, ifenslave and bridge-utils) would take a second implementation and, for ifupdown, host packages. With `UNOS_HOST_EXEC=local` every route answers 503, as the firewall's do (ADR-0416). No host package is added; `networkctl` joins `HOST_TOOLS` (systemd).

**The files** (`supervisor/src/network/virtual.py`). Each interface is a `.netdev` and a `.network` file of networkd's own, `05-unos-<name>.netdev` and `.network`; a port is `04-unos-<master>+<port>.network` (`Bond=` or `Bridge=`), and a VLAN's parent gets `04-unos-<parent>.network`: the settings of the file networkd applied to it (`networkctl status`, a `.network` file of networkd's folders) without its `[Match]`, the host's own `VLAN=` lines included, with `Name=<parent>` and the `VLAN=` of each of UNOS's VLANs on it, because a drop-in of netplan's `Name=e*` file would attach the VLAN to every card. A file with drop-ins of its own is not taken over (409): UNOS would not carry them. Interfaces that do not take over a port's settings, and ports, get `RequiredForOnline=no`, so that the boot does not wait for them. `04-` and `05-` come before every file of the host's (netplan's are `10-netplan-*`), and networkd applies the first file that matches. The `.netdev` holds the interface's metadata as a comment line (`# unos: {...}`, with the list of its files); UNOS lists, and deletes, only the interfaces of those lines, with exactly their files, and the parent's file goes with its last VLAN. Live, the files are in `/run/systemd/network`, which networkd reads; the kept ones are in `/etc/unos/netdevs`, written in the order of the change (an interface's files before the files that name it, and after them when it goes), each atomically, so that a power cut never leaves a kept file that names a missing interface. The host's unit `unos-netdevs.service` (`Before=systemd-networkd.service`, wanted by it) copies them into `/run/systemd/network` at boot; UNOS writes and enables it when it first keeps an interface and removes it with the last. It copies the `.netdev` files first, so that a copy that stops part way names no interface it lacks. A change that is not kept therefore never outlives a reboot, also when the administrator pulls the plug in a panic. The entry asked for the changes to survive a reboot "in the host's own network configuration": they are networkd's own files, which networkd itself applies, but they reach it through UNOS's unit rather than from `/etc/systemd/network`, because `/etc` outranks `/run` for the same file name, so neither an unkept change nor the pending deletion of a kept interface could be staged in `/run`, and a reboot within the revert's time would keep it.

**What a change must not cut** (`protected`): the interfaces of the IPv4 and IPv6 default routes (each next hop of a multipath route) and of the host's route to the asking computer (`ip route get`), with what they rest on (a VLAN's parent, a bond's or bridge's ports), again and again. A change touches the interfaces whose files it changes or that it releases or removes: a new bond's or bridge's ports, a new VLAN's parent (networkd applies the parent's settings again, which drops and asks again for its DHCP lease), and for a deletion the interface, its ports and its parent. A change that touches a protected interface waits to be kept; any other, such as a bridge with no port or only other interfaces, or a VLAN on another card, is kept as soon as networkd has made it.

**The revert**, as the firewall's (ADR-0416) and the interfaces' (ADR-0244): every change first records in `/run/unos/netdevs` on the host its ordered ops (add, replace, remove), copies of the files it replaces or removes, the interfaces it makes and what it is (`create bond bond0`). A change that waits then writes the marker `pending` and arms the transient timer `unos-netdevs-revert` (`systemd-run --on-active=120`); without both nothing changes (500). After 120 seconds the host undoes it without the supervisor: the files back in reverse order, the interfaces it made deleted (`ip link delete`; networkd removes none), `networkctl reload`, which applies the host's own files again; a revert that fails leaves `failed`, which `GET` reports. `POST /network/virtual-interfaces/confirm` keeps it: the Keep and the revert both start by taking the marker (Keep renames it `kept`), so only one acts, then the change is written to `/etc/unos/netdevs`. A change that networkd does not make within 20 seconds as its files say (the interface, its ports' master, a VLAN's parent and id, a bond's mode, no link that networkd failed to configure) or whose commands fail is undone at once, and by the timer when that fails or the host does not answer; its marker then becomes `undoing`, which the revert takes and a Keep does not, so a change that failed is never kept, and `GET` reports it as being undone. A step of the undo that fails does not stop the others, and networkd is reloaded in any case. One change waits at a time (409); before the next, a Keep that could not be written is written and an interrupted change is undone.

**A bond or bridge that takes a protected port** (at most one: two are refused, 409) takes over that port's network: the sections of its `.network` file that say how it gets addresses and routes (`[Network]` without `Bond=`, `VLAN=` and the like, `[Address]`, `[Route]`, `[DHCP]`, `[DHCPv4]`, `[DHCPv6]`, `[IPv6AcceptRA]` and the other address sections), its MAC address (`MACAddress=` of the `.netdev`) and, when its DHCPv4 lease's client identifier is the DUID kind and the file sets none, the lease's IAID, so that the DHCP server sends the same address. A port whose file makes or joins other interfaces (`Tunnel=`, `VXLAN=`, `VRF=` and the like) is refused.

**Values** (ADR-0293), checked before they reach a file or a command: names of 1 to 15 letters, digits, `_`, `.` and `-` starting with a letter, none that the host has, and none of `lo`, `all`, `default`, `bonding_masters`, `unos-wg`, `docker*`, `dummy*`, `br-*` or `veth*`; VLAN ids 1 to 4094, a VLAN name defaulting to `<parent>.<id>`, and no second VLAN of an id on one parent; the MTU 1280 to 9216; bonds of 2 to 8 wired network cards (sysfs's `device`, no `wireless`), mode `802.3ad` (with `TransmitHashPolicy=layer3+4`) or `balance-rr`, `MIIMonitorSec=100ms`; bridges of 0 to 8 ports, cards, bonds or VLANs, `STP=no`; a port in no bond or bridge (`master`, and UNOS's own records), with no VLAN on it, without addresses but the link-local ones (it would lose them) unless it is the protected port whose settings are taken over, and without a disable that waits to be kept (ADR-0244); a VLAN on a wired card or a bond that networkd manages. An interface that takes no port's network gets none, DHCPv4 without the server's gateway, routes and DNS (it never takes the default route), or 1 to 4 static addresses without a gateway; never IPv6 router advertisements. An interface with VLANs on it or that is a bridge's port is not deleted (409).

**The API** (`supervisor/src/network/virtual_router.py`, administrators only, the `network` area of API tokens): `GET /network/virtual-interfaces`, `POST .../bonds`, `.../vlans`, `.../bridges`, `DELETE .../{name}`, `POST .../confirm`. The audit log gets `network_interface_created`, `network_interface_deleted` and `network_change_kept`. System > Network's card (`webui/src/lib/components/network/VirtualInterfacesCard.svelte`) warns in the dialog when a change will wait to be kept, counts down, offers Keep and says what the host did when the time ran out.

Tests: `supervisor/tests/test_virtual_interfaces.py` (the API against a fake networkd host), `supervisor/tests/test_virtual_interfaces_scripts.py` (the host scripts under sh and dash, and the boot unit's copy), `webui/tests/network-virtual.spec.ts`.

## Consequences

- A VLAN on the uplink waits to be kept, and the uplink's DHCP lease is asked for again when it is made, kept or removed; where the server answers another address, the change cannot be kept from the page and is undone.
- A bond needs two network cards: the dev device, which has one, shows only the refusal of a bond of its uplink alone (its revert is shown by a VLAN on the uplink); a bond is the owner's to check with a USB network adapter.
- A bridge or bond that took over the uplink, and a VLAN's parent, keep a copy of the settings of the file they took them from and do not follow later edits of netplan; a bond's or bridge's IPv6 privacy and stable addresses may differ from the card's.
- Two cards that both have addresses on the LAN, such as two cabled cards with DHCP, cannot be bonded at once: the second card's cable is unplugged, or its addresses removed, first.
- A NetworkManager or ifupdown host gets no bonds, VLANs or bridges from UNOS until a later change builds them.
- `deploy/uninstall.sh` removes `/etc/unos`, and with it the kept interfaces: they stay until the next reboot, after which the host's own configuration applies again, so an uninstall never cuts the host off at once. It leaves `unos-netdevs.service`, which does nothing without its folder (`ConditionPathIsDirectory`); `systemctl disable unos-netdevs.service` and removing its file are by hand.
- A Docker macvlan network on a card that becomes a port loses its parent; UNOS does not see Docker's networks.

## Considered options

- The files in `/etc/systemd/network` at once: Keep would need nothing, but a reboot within the revert's time would keep a change that cut the host off.
- The files in `/run` until Keep, then moved to `/etc/systemd/network`: the deletion of a kept interface could not be staged in `/run`, which `/etc` outranks, and networkd would take the moved files as changed and apply them again at its next reload.
- Drop-ins of the parent's own `.network` file for VLANs: netplan's file matches every card, so the VLAN would land on any of them.
- A UNOS unit that makes the interfaces with `ip` at boot: networkd would apply netplan's catch-all to them, and the host's own configuration would not hold them.
- NetworkManager's checkpoints, which roll back by themselves: only for NetworkManager hosts, and lost with NetworkManager's restart.
