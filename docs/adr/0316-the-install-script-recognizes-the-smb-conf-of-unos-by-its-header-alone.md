# ADR-0316: The install script recognizes the smb.conf of UNOS by its header alone

## Context

`configure_samba` of `deploy/install.sh` kept an existing `/etc/samba/smb.conf` that had the
line `server string = UNOS NAS` anywhere, for installations of releases that had not imported
their shares into the database yet: their shares existed only in that file. UNOS has no such
installations (ADR-0207), and every smb.conf that the supervisor writes starts with its header
(`HEADER` of `supervisor/src/shares/smbconf.py`, ADR-0074). The ledger entry
`deploy.no-legacy-smb-conf-recognition` asks for the header line alone; the agent took it up
under the owner's delegation ("work on through the features, ask no questions; I allow
everything", in translation, 2026-11-09).

## Decision

- `configure_samba` keeps an existing `/etc/samba/smb.conf` only when its first two lines are the
  header that the supervisor writes (`HEADER`, which starts with `# Generated by UNOS from its
  database.`), as the supervisor's own check (`unos_header` of `smbconf.py`) counts a file as
  its own; then it only starts Samba. The file it writes otherwise, `render_config([])`, is the
  function `unos_smb_conf`, and the check compares with its first two lines.
- Any other file, one that only has `server string = UNOS NAS`, a part of the header or the
  header below its first line, with leading blanks, a byte order mark or CRLF line ends
  included, is handled like any other smb.conf of the host: replaced, and kept as
  `smb.conf.original` only when there is none yet.
- `server string = UNOS NAS` stays in the `[global]` that ADR-0281 pins, but marks no file of
  UNOS: the remark of ADR-0281 that `install.sh` recognizes a file by it no longer holds.
- Tests: `TestInstallScript` of `supervisor/tests/test_deploy_scripts.py`,
  `test_rerun_keeps_a_file_that_starts_with_the_unos_header`,
  `test_a_file_that_does_not_start_with_the_unos_header_is_replaced`,
  `test_a_rerun_keeps_no_copy_of_a_file_it_replaces` and
  `test_rerun_keeps_the_smb_conf_that_unos_generated`.

## Consequences

- The first run keeps the host's smb.conf, which the samba package installed, as
  `smb.conf.original`; a later run that replaces a file keeps no copy of it. A file written by
  hand with UNOS's server string, and a file of UNOS whose first lines someone changed, are such
  files: share sections added to them by hand are gone, where the supervisor's next apply would
  have kept them in `smb.conf.unos-replaced` (ADR-0092).
- A file of UNOS cut off in its header, as an interrupted write leaves it, is replaced by a
  complete one, as before.
