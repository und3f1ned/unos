# ADR-0381: An app of several containers installs through the Docker API with pinned images and a password on its pool

## Context

The owner's words for this work, in translation: "first Immich of several containers must appear" and "so install it", under the standing delegation "work on through the features, ask no questions; I allow everything" (as for ADR-0340). Every app of the catalog is one container (`supervisor/src/apps/router.py`): the installed list, the actions and the audit work per container, an install pulls a floating tag and checks no port, and the `VOLUME`s an image declares become anonymous volumes in Docker's data root, which is on the dev device's SD card (ADR-0228). The catalog's Immich is one `immich-server` container whose `DB_HOSTNAME` and `REDIS_HOSTNAME` name containers that do not exist, on Docker's default bridge without name resolution, so it cannot work, and ADR-0377 left Immich's NPU to an Immich of several containers. Immich v3.4.1 runs four: its server, Postgres with VectorChord, Valkey and its machine learning service, which find each other by name and share the database's password.

## Decision

- **Engine.** UNOS creates the containers of an app itself through docker-py over the Docker socket, as for every app: no Compose, no docker CLI, no YAML. Compose cannot express ADR-0377's per-path `MaskedPaths`, and the rules of every app stay in one place: the `unos.app` labels, `prepare_app_start` and the pools' refusals (ADR-0318), the 503 of ADR-0323, the worker threads of ADR-0254 and the capped logs of ADR-0330. The ledger entry keeps its id `apps.compose-stacks`; its "compose" is historical.
- **Model** (`supervisor/src/apps/schemas.py`). An app is its main container, from the template's own fields, plus the companion containers of `AppTemplate.companions`. Both are a `ContainerSpec`: `image`, `volumes`, `environment`, `hardware`, `tmpfs` (container path to Docker's tmpfs options), `shm_size` and `stop_timeout`; a `Companion` adds its `name` (`^[a-z][a-z0-9-]*$`). `AppTemplate.depends_on` names the companions that must be ready before the main container starts. `EnvVar.editable=False` marks wiring that UNOS sets: an override of it answers 400. Companions publish no port, are never privileged, get no capabilities, no `network_mode` and no overrides, and an app with companions cannot run in the group unos-smb (ADR-0274). The one-container templates are unchanged.
- **Identity.** One instance per template: `AppInstallRequest.name` is removed (ADR-0207), because the data folders are named after the template id and a second instance would share them. Every container of an app carries `unos.app=<template id>` and, with its pool data, `unos.app.pool`; a companion also carries `unos.app.companion=<name>`, and the main container `unos.app.name` and `unos.app.icon`. The main container is named `<id>`, a companion `<id>-<name>`. The containers of an app with companions share the bridge network `unos-app-<id>`, labelled `unos.app=<id>`, on which each companion answers to its name as a DNS alias; no subnet is given, and the supervisor's attachment to `unos-net` keeps Docker's address pools off its subnet (ADR-0048). The routes stay `/apps/installed/{container_id}/...`, and any container of an app names the whole app.
- **A password on the pool.** A `VolumeMapping` with `generated_secret=True` is a password file that the install creates when it is missing, beside the data it unlocks (Immich's `{pool}/apps/immich/postgres/password`): `secrets.token_hex(32)`, owned by root with mode 0600, written to a temporary file opened with `O_EXCL` and `O_NOFOLLOW` in the folder reached by `open_dir_nofollow` (ADR-0042), fsynced, linked to its name (a file that appeared meanwhile is kept) and its folder fsynced, before the first container that reads it is created. It is bound read-only and named by a `*_FILE` variable (`DB_PASSWORD_FILE`, `POSTGRES_PASSWORD_FILE`), so its value is never in Docker's configuration, a label, an answer, the audit log or a log line. `secret_for` names the data folder that was initialised with it: a missing file beside a non-empty folder answers 409 (Postgres keeps its first password), and so does a file that is a link, empty, longer than 256 bytes or not letters and digits; UNOS neither shows nor replaces it. A start never creates it: its source is not creatable after the install.
- **Pinned images.** The images of an app with companions are `name:tag@sha256:<index digest>`, as ADR-0305 pins the Dockerfiles: they are pulled by digest (`images.pull(name, tag=digest)`), containers are created from `name@digest`, and the tag is added afterwards for the Images tab, a failure of which only logs a warning. `PinnedImage` of `supervisor/src/apps/catalog.py` holds each pin with an estimate of its size on the system disk; one `IMMICH_VERSION` names the server's and the machine learning's tags, tied by a test. `UNPINNED_TEMPLATES` lists the templates that still use a floating tag and may only shrink; `apps.pinned-catalog-images` empties it.
- **Checks before the first pull, on every install.** In one worker thread under a lock per app (another change of the same app answers 409): the template, the request (an override of a fixed variable, a host port outside 1 to 65535, a host port given twice or a moved port of an app in the host's network answer 400), the environment, the pool, the planned folders of all containers (no nested sources, the share-folder rules per container) and the password files. Then one `containers.list(all=True)`, the first Docker request (503 when Docker does not answer, ADR-0323): an app already installed, complete or not, and another container with one of the app's names answer 409. A network `unos-app-<id>` that is not the app's answers 409; the app's own, left without containers, is reused. The host ports of the main container, after overrides, are checked against the `PortBindings` of every container, stopped ones too, and against `ss -H -l -n -t -u -p` on the host (`src/host.py`, ADR-0020): a port in use answers 409 that names the container or the process and asks for another host port. An app in the host's network (`network_mode` `host`: Home Assistant, Scrypted) binds its container ports on the host itself, because Docker discards the port bindings of such a container: its container ports are the ones checked, an override that moves one answers 400, and a taken one answers 409 that asks to remove that container or stop that program instead. When `ss` fails, a warning is logged and Docker's own bind at the start is the last check. The system disk must keep at least 2 GiB free after the images that are not present yet (the lower `df` of Docker's root folder and `/var/lib/containerd`), or 409 asks to remove unused images first; a `df` that fails answers 500. A host that has neither folder, as when the supervisor does not run on Docker's host (the compose test stack), has no file system to read: a warning is logged and the install goes on, as when `ss` fails. After the pulls and before any write, every `VOLUME` that a pinned image declares must lie at or under a bind or tmpfs target of its container, or 500 with nothing installed.
- **Order and readiness.** After the pool's folders and password files, the network is made, then the containers are created, the companions in catalog order and the main container last, and started in the same order. Before the main container starts, each companion of `depends_on` must be ready: healthy when its image has a health check, otherwise running and not restarting 2 s after its start, within `DEPENDENCY_READY_SECONDS = 180`; one that exits, dies or turns unhealthy fails at once, with its exit code or the last output of its health check. The answer does not wait for the main container's own health (`health: "starting"`). Start, Stop, Restart and Uninstall act on every container of the app: start runs `prepare_app_start` for all before it starts any, in the install's order and with its waits; stop runs in reverse with `stop(timeout=stop_timeout or 10)`; restart is a stop of all, then a start of all, for one-container apps too; uninstall stops all, removes each without its volumes and removes the app's network (one that a foreign container uses stays and the audit entry says so), and keeps the data folders, password files and images (ADR-0256). An app that lacks a container (`missing`) does not start (409) and can be uninstalled. At boot dockerd starts every container in no order, and the restart policies bring the app up (ADR-0307).
- **A failed install leaves nothing in Docker.** A failure while the network is made or the containers are created, started or awaited removes, forced and in reverse order, every container the request created and the network if it made it, and answers 500 with the failing step and "its containers were removed and its data folders kept"; folders, password files and pulled images stay. Nothing is audited when that clean-up succeeds; when it fails, the answer and an `APP_INSTALLED` entry with success false name what was left behind (ADR-0350).
- **The system disk.** Every `VOLUME` an image declares is bound to the pool, and paths that the containers write at run time get a tmpfs: the `/tmp` of Immich's server and of its machine learning (gunicorn's heartbeat), and Postgres's `/etc/postgresql` and `/var/run/postgresql`. Immich's library `/data`, its database, Valkey's `/data`, the model cache `/cache` and the password live under `{pool}/apps/immich/`. Only the images, the container records and the capped json logs are on the SD card. No read-only root filesystem and no memory limit: the device check measures them first, and limits belong to `apps.container-resource-limits`.
- **Immich** (`supervisor/src/apps/catalog.py`): the main container `immich` (`ghcr.io/immich-app/immich-server:v3.4.1`, port 2283, `/data` on the pool, the host's `/etc/localtime` read-only, the password file, `/tmp` in RAM; `DB_HOSTNAME=database`, `DB_USERNAME`, `DB_DATABASE_NAME`, `DB_PASSWORD_FILE`, `REDIS_HOSTNAME=redis` and `IMMICH_MACHINE_LEARNING_URL=http://machine-learning:3003` not editable; `depends_on` database and redis) and the companions `database` (`ghcr.io/immich-app/postgres:14-vectorchord0.4.3-pgvectors0.2.0`, `POSTGRES_PASSWORD_FILE`, `POSTGRES_INITDB_ARGS=--data-checksums`, `DB_STORAGE_TYPE=HDD`, `shm_size` 128m, `stop_timeout` 60), `redis` (`docker.io/valkey/valkey:9`) and `machine-learning` (`MACHINE_LEARNING_MODEL_REVISION=v2`, whose image ADR-0382 chooses), each pinned by digest. Immich's external library from a share is left out: without the group option ADR-0274 refuses a share's folder for an image that runs as root.
- **BookStack, Paperless-ngx and Linkwarden** leave the catalog: each needs a database or a broker that a one-container template never gave it. `apps.catalog-companions` brings them back as apps with companions.
- **API.** Besides the removed `name`, the changes add fields: `InstalledApp` keeps the meaning of its fields for the main container (`status` is `missing` without it) and adds `health`, `companions` (name, container, container_id, status, health, image, devices) and `missing`; `AppVolume.companion` names the container of each volume; `AppInstallResponse` adds `health` and `companions`. No route and no `AuditAction` is added; the audit texts name the containers and the generated password file's path, never its value.
- **Not in this entry.** Updating an app keeps its data and can be rolled back only with a copy of its database taken before the new version migrates it: `apps.update-in-place`. The install as a background job that reports its progress: `apps.install-progress`.
- **Tests.** `supervisor/tests/test_app_stacks.py` against the strict fake Docker of `supervisor/tests/docker_fake.py` (the order of every call, labels, aliases, mounts, the rollback at each step, the password file and its absence from every call and log, the checks before the pull, the listing and the actions), `TestPortCheck` and `TestSystemDiskSpace` of `supervisor/tests/test_apps.py`, the catalog's tests (companions, pins, the ratchet, the removed templates) and `webui/tests/apps-stacks.spec.ts`. The device check is by hand, from the notes of the ledger entry: the owner deploys, pulls and installs (ADR-0211), the install with `scripts/dev/api.py --timeout 3600`, since the API answers only after the pulls, and the guard reads the values of api.py's `--param` and `--timeout` as values, not as the method.

## Consequences

- An install of Immich writes about 3.6 GB to the dev device's SD card once (the compressed blobs and the unpacked snapshots of the containerd image store), and about 1.5 to 2.4 GB again for each later version; the cost is accepted because the owner asked for Immich on the device. Docker's data root on the pool's disk is a separate decision (`device.docker-data-root-on-hdd`, ADR-0228).
- The pool's hard disk does not sleep while Immich runs (Postgres, Valkey's snapshots, the health checks, Immich's jobs), so ADR-0378's idle timeout does not act; stopping Immich lets it sleep.
- At boot Immich's server may restart once or more before its database answers (ADR-0307).
- Valkey has no password: it is reachable only from the app's network and from the host.
- The Containers page still stops, starts and removes one container of an app at a time; an app with a removed container shows as incomplete, and Uninstall cleans it up.
- A database folder deleted by hand is created again empty at the next start and the kept password initialises it.
- Updating Immich, until `apps.update-in-place`, is an uninstall and an install of a newer catalog after a snapshot of the pool: Immich migrates its database forward and refuses a downgrade.
- An install of an app that publishes ports reads `ss` on the host, unless containers already publish every one of them (an app without ports reads nothing of it), and every install reads `df`; a taken port of a one-container app now answers 409 before the pull instead of 500 at the start, and the port of an app in the host's network cannot be moved.
- BookStack, Paperless-ngx and Linkwarden cannot be installed, and an install request with `name` is refused.
- The database's entrypoint reads the password file as root, before it drops to the postgres user; should the device show it cannot, the database's mapping of the file gets uid and gid 999, with mode 0600 kept.

## Considered options

- Compose on the host through `src/host.py`, or the Compose CLI in the supervisor's image: Compose has no per-path `MaskedPaths`, only `systempaths=unconfined` (refused by ADR-0377), UNOS would depend on the host's Compose version, and the rules of every app would exist twice.
- A flat list of services without a main container: every one-container template, the installed list and the web UI would change for nothing.
- The password in the environment (Docker's configuration on the SD card and `docker inspect` show it), in the supervisor's `/data` (separated from the database it unlocks) or in a folder of secrets of its own: the file beside the database moves with it in the pool's snapshots.
- Read-only root filesystems, fixed memory limits, Valkey in RAM (its queued jobs lost at a restart) and a Postgres command line that moves its statistics: none measured; the device check measures first.
- Routes by app id, refusing the removal of a companion on the Containers page, and starting the pool's apps in order after a mount: more change than the problem needs.
