# ADR-0417: Every data path of the supervisor follows UNOS_DATA_DIR, read once at its start, and the stand-in patches no constant

## Context

About 25 module constants of `supervisor/src` named paths under `/data`, and the health check read `/data/unos.db` inside its handler. To run the supervisor outside its container, `scripts/standin/run_supervisor.py` replaced those constants one by one after the import, and the host files' constants too (fstab, the served certificate's folder, the updater's backups, the mount table, `/mnt`, restic's host name file, the web UI's TLS address): a constant that it missed would have written to `/data` of the workstation. The entry `architecture.configurable-data-dir` asks for one setting of every data path, host paths with settings of their own, and a stand-in that patches no module constant.

## Decision

- `supervisor/src/paths.py` is the one module of `supervisor/src` that names `/data` or makes a path in the data directory. It reads `UNOS_DATA_DIR` once, when it is first imported: unset or empty, `/data` (the `unos-data` volume of the supervisor's container); otherwise an absolute path of an existing directory. Any other value raises `DataDirError` at the import, so the supervisor refuses to start (`data_dir_from`). It defines every data path with the name it has under `/data` today: the database `unos.db`, `app-catalog.json`, `audit/audit.jsonl`, `backups/`, `certs/`, and the state files of the RAID status, the SMART history, the volume use, the notifications and their history, the off-device copy's settings, secrets and status, the power, UPS and Wake-on-LAN settings, the scheduled tasks, their runs and backup keys, and the updater's state, history and settings.
- Read once, never at call time: the modules bind their names (`AUDIT_FILE`, `CONFIG_FILE`, `CERTS_DIR` and the others) from `src.paths` at their import, as they bound the literals before. The directory is then one for the whole life of the process and validated once, no request reads the environment, and tests keep moving a module's path with `monkeypatch.setattr`. `supervisor/tests/conftest.py` sets `UNOS_DATA_DIR` to `<the process's folder of ADR-0383>/data` before anything imports the supervisor, so no test reaches `/data`; that folder is read-only, as `/data` was to the tests, so a test that writes a path it did not move fails instead of leaving a file to the next tests of its process; no test changes the variable in its own process, where it would read the paths of the start (`test_data_dir.py` fails for a test file that names it, but `conftest.py`, `test_data_dir.py` and `test_standin.py`, which give it to child processes).
- `UNOS_DB_PATH` and `UNOS_APP_CATALOG_PATH` stay settings, with `paths.DATABASE` and `paths.APP_CATALOG` as their defaults; the JWT secret stays beside the database. Every user of the database's file takes `settings.db_path`, the file the engine opens: the backups, the scheduled backups (`DB_FILE` of `supervisor/src/scheduler/router.py`), the updater (`DB_FILE` of `supervisor/src/updates/updater.py`), the emergency command line and `GET /api/v1/health/full`, which reads the RAID status and the UPS settings through `raid_status_or_none` and `saved_ups_config`.
- Host paths, and the container's paths outside its data volume, keep settings of their own, which `UNOS_DATA_DIR` does not move: `UNOS_SMB_CONF_PATH`, `UNOS_NFS_EXPORTS_PATH` and `UNOS_POOLS_BASE_PATH` as before, and new fields of `Settings` in `supervisor/src/config.py` for the constants that the stand-in replaced: `UNOS_FSTAB_PATH` (`/etc/fstab`, its backup `<path>.unos-backup` beside it), `UNOS_MOUNTS_BASE_PATH` (`/mnt`), `UNOS_SERVED_CERTIFICATE_DIR` (`/served-certificate`), `UNOS_UPDATE_BACKUP_DIR` (`/var/lib/unos/backups`) and the web UI's TLS address, `UNOS_WEBUI_TLS_HOST` (`webui`) and `UNOS_WEBUI_TLS_PORT` (443). The defaults are the values of before; a path setting that is not absolute stops the start. `/run/samba` stays fixed: it is Samba's own folder on the host, which smb.conf names in its `[global]` section (`supervisor/src/shares/smbconf.py`, rendered byte-identical, ADR-0082), not a file of the supervisor. The mount table `/proc/self/mountinfo` and restic's `/proc/sys/kernel/hostname` stay fixed too: a mount table of another file would turn the file manager's mount-point check off.
- `scripts/standin/run_supervisor.py` sets `UNOS_DATA_DIR` and those settings in the supervisor's environment (`stand_in_environment`), and patches no module constant. It replaces functions only, `on_system_disk`, `on_system_filesystem` and `probe_store` of the off-device copy, `reload_caddy` of the served certificate and, on a machine without `/proc` (macOS), the file manager's `_read_mount_points` with an empty table, and turns the login limiter off: no setting may turn off the system-disk check, the S3 probe, the mount-point check or the login limit on a NAS. The fake `unshare` of `supervisor/tests/fake_restic.py` gives its command the fake's `hostname` file in place of `/proc/sys/kernel/hostname`, the file of the UTS namespace that it does not make. `configure()` refuses to run as root and once the supervisor is imported, whose paths would not be the stand-in's.
- `deploy/install.sh` had a variable of the same name for the host's `/var/lib/unos`, which it only created, while `update.sh` and `uninstall.sh` name that folder fixed. It is removed, so that one name means one thing: `install.sh` creates `/var/lib/unos`, and `docs/INSTALL.md` no longer lists the variable.
- The compose files set no `UNOS_DATA_DIR`: the device keeps `/data`, and nothing changes there (`test_data_dir.py` checks both compose files).
- Tests: `supervisor/tests/test_data_dir.py` starts the supervisor twice with `UNOS_DATA_DIR` naming two folders and the host settings naming folders of the test, and finds every data path in its folder with its name of `/data`, the database, the generated secret (mode 0600) and the audit entry of the setup there, the health check reading them, nothing else changed between the two starts and every host path where its own setting puts it; it also checks the host settings' defaults, the values refused and the refused start. `supervisor/tests/test_standin.py` finds no `/data` literal and no path made from `DATA_DIR` in `supervisor/src` outside `src/paths.py` (but the apps' paths inside their containers), no module constant patched by `run_supervisor.py` (`STAND_IN_SWITCHES`), and no `/data` path left in the stand-in's modules.

## Consequences

- A new data path is added to `src/paths.py` and to `DATA_PATHS` of `test_data_dir.py`; a `/data` literal or a path made from `DATA_DIR` anywhere else fails `test_standin.py`.
- Importing the supervisor needs an existing data directory: a script that imports it outside the container sets `UNOS_DATA_DIR` (`scripts/catalog-platforms.py` names the temporary directory, where nothing is written).
- A test that wants a data folder of its own moves the module's names (`test_api_times.py` moves every global under `paths.DATA_DIR`).
- The settings of the host paths can be set on a NAS too, by root through the compose files; nothing sets them there. `UNOS_MOUNTS_BASE_PATH` moves, with `UNOS_DATA_DIR`, what the off-device copy counts as the system disk, as `UNOS_POOLS_BASE_PATH` moves the pools.

## Considered options

- Reading `UNOS_DATA_DIR` at every call, through functions of `src/paths.py`: a test that changed the variable would see it, but every caller and about 250 patches in the tests would change, a running supervisor could see its directory change under it, and every use would read the environment.
- Folding the host paths under `UNOS_DATA_DIR`: they are the host's files, not the supervisor's data (the entry's second step).
- Settings that turn off the system-disk check, the S3 probe or the login limit for the stand-in: a switch that would weaken a NAS if it were set there.
