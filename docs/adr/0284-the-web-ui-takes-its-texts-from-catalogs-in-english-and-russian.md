# ADR-0284: The web UI takes its texts from catalogs in English and Russian, chosen on the Account page and checked by make frontend

## Context

ADR-0023 lists the English-only web UI as debt, and the feature `webui.translations` asks for Russian first. Every text was inline English in the .svelte files, the E2E specs find elements by those texts, and an i18n library is a new npm dependency, which is the owner's call (webui/AGENTS.md). The work comes in two phases: this one builds the catalogs, the choice of language, the check, and translates the frame, the sign-in, setup and Account pages and the shared components; later branches translate one area each, in parallel.

## Decision

- No library. `webui/src/lib/i18n/translate.ts` looks a key up in the current language, else in English, else returns the key itself, fills `{name}` placeholders and picks a plural form by `Intl.PluralRules` from `params.n`. `webui/src/lib/i18n/index.ts` has the stores `locale`, `t` (`$t('area.key', params)`) and `intlLocale` (for dates).
- Catalogs: `webui/src/lib/i18n/catalog/<area>.ts` exports `en` and `ru: Translation<typeof en>`, keys start with `<area>.`, and a text with a count has the plural forms of its language (`one` and `other` in English; `one`, `few` and `many` in Russian). `import.meta.glob('./catalog/*.ts', { eager: true })` collects them: a new area adds its file and edits no shared one. `common.ts` holds the words that many areas use; this phase adds `layout`, `login`, `setup`, `system`, `account` and `ui`.
- The choice: the Account page (System > Security for an administrator, Account for a regular user) has a Language card that offers English and Russian, each named in its own language. It applies at once and is kept in this browser's `localStorage` as `unos-locale`: it belongs to the browser, not to the account, so the sign-in page shows it too. Without a saved choice the language is Russian when the primary subtag of `navigator.language` is `ru`, else English. `<html lang>` follows it. Dates and times take the browser's own locale when it is of the chosen language (an en-GB browser keeps British dates, an en-US one American dates), else the chosen language with the day first and a 24-hour clock: `en-GB` for English, `ru` for Russian (`dateLocale` of `translate.ts`). Before the catalogs every date took the browser's own format; an English page in a Russian or a German browser keeps the day first, and does not write 8 November as 11/8.
- Values that the server answers as words, such as a firewall rule's action, direction and protocol, the default policies and a certificate's type, are shown through a map from the value to a key of the catalog (`{ allow: 'account.firewall.allow' }`), and a value without a key as it comes. A certificate's dates, which the server answers in openssl's English form, are shown in the language of the page.
- English stays: the server's messages (the API's `detail`, shown as it comes; the route fakes copy them, ADR-0189), the client's stand-ins for a missing one in `webui/src/lib/api/client.ts` ("Request failed", the rate-limit text) and the developer console.
- The specs run in English: `webui/playwright.config.ts` sets an en-US browser, and the English half keeps the existing texts word for word. `webui/tests/language.spec.ts` switches an administrator's Account page to Russian and back, through reloads and the sign-in page; switches a regular user's Account page to Russian, through a reload; shows the firewall's and the certificates' values in both languages; and checks the default of a browser set to Russian and the dates of an English page in it.
- The check, `webui/scripts/i18n-check.mjs` (`npm run i18n`, which `make frontend` runs), reads every .svelte file with svelte/compiler, and its scripts and the expressions of its markup with TypeScript. It fails for a text with letters that does not come from `$t`: text between tags; the value of a user-facing attribute or prop (placeholder, title, alt, aria-label, label, hint, description, error, a prop named ...Label, ...Hint, ...Text and the like), or of any prop of a component when the value does not look like code; and any string literal of a script or of an expression of the markup (blocks, `{@const}`, directives, props), wherever it goes: a variable, a property, an argument, a return value, a thrown error, a placeholder of `$t`. A literal is not a text where it is compared or looked up, where it names a module, a type, a key of an object, an argument of `console`, or the key of `$t`, where it goes to a class or a style, and where it looks like code: a name, an id or a class, a path, a URL, a MIME type, a locale, a CSS length. Where a text goes (a variable, a prop or a property named like a text, `confirm()`, `alert()`, `prompt()`, a placeholder of `$t`) or where the markup shows it, even a name is a text. A comment `i18n-ignore: <reason>` above a statement or a property exempts its literals, for a command or a name that is the same in every language; the summary counts them and review reads the reasons. It fails for a `$t` key that no catalog has, also a literal key of a map (a literal that starts with the name of a catalog and a dot), a plural text without `n`, and a catalog whose `ru` half differs from `en` in keys, plural forms or placeholders, or holds an empty text. `webui/scripts/i18n-untranslated.txt` lists the files not translated yet, by area with blank lines between the groups, so that git merges branches that take off different areas; a listed file with nothing left to translate fails. `supervisor/tests/test_i18n.py` tests the check and the lookup.
- The empty list is necessary, not sufficient: `webui.translations` passes once that list is empty and a walk through every page in Russian, by a reviewer in a fresh context (ADR-0017), finds no English text other than what stays English above. The check cannot see a text that the code puts together from data at run time, nor the texts of .ts modules (Consequences).
- The `ru` halves of the catalogs, the name of Russian in `LANGUAGES` of `webui/src/lib/i18n/index.ts`, the Russian texts that `webui/tests/language.spec.ts` expects, and the Russian demo catalogs and expected lookups of `supervisor/tests/test_i18n.py` are the web UI's Russian texts and their tests; everything else in the repository stays English (ADR-0200). The Language section of `AGENTS.md` points here.

## Consequences

- Out of the check's reach, and so for review and the walk through the pages: a text that the code puts together from data at run time (a value of the server shown as it comes, as `rule.action.toUpperCase()` did), a single lower-case word in a script, which the check takes for a name (`status = 'idle'` shown later), and the texts of .ts modules (`webui/src/lib/components/shares/texts.ts` and `access.ts` there). webui/AGENTS.md says to translate them too.
- A Russian page shows the server's messages in English, and a text set by an action stays in the language it was set in until the next action.
- Both languages are in the main bundle.
- The catalogs are TypeScript, so svelte-check also fails for a missing or an extra key of a `ru` half.

## Considered options

- An i18n library (svelte-i18n, typesafe-i18n): a new dependency is the owner's call; the store and the lookup are about 100 lines.
- One catalog file per language: every branch of the second phase would edit the same two files.
- Translating the server's messages: that needs error codes from the API, outside this feature.
- A check that reports only the script literals that go to a variable or a property named like a text, or that the markup shows: a review found about 70 texts it did not see in the files still listed, in objects, arguments, return values, `{@const}` and `{#each}`, so every literal is a text unless it is code.
- For dates on a page of another language than the browser's, the bare language (`en`): that is en-US, month first with a 12-hour clock, which reads 8 November as 11 August to most of the world.
