# ADR-0382: Hardware profiles apply per container, may choose the container's image and give Immich's machine learning the RK3588's NPU

## Context

ADR-0377 gave Jellyfin the video hardware of the dev device's RK3588 through the hardware profiles of a template, applied to the app's one container, and left Immich's NPU out because it belongs to a second container. With apps of several containers (ADR-0381) Immich's machine learning is a companion container, and the owner asked for Immich on the device under the standing delegation of ADR-0377. Immich v3.4.1 uses an RK3566, RK3568, RK3576 or RK3588 NPU only in its `-rknn` image of the machine learning (arm64 only, with Rockchip's `librknnrt`), which needs Rockchip's RKNPU driver 0.9.8 or later, a DRM device in `/dev/dri` under the vendor kernel (the dev device has 0.9.8), and names the SoC from `/proc/device-tree/compatible`, the link into `/sys/firmware` that Docker masks and `docker-default` denies, as MPP does; Immich's own example passes all of `/dev/dri` with `systempaths=unconfined` and `apparmor=unconfined`. Elsewhere the same service needs the image without the suffix, and Immich's server transcodes with RKMPP given Jellyfin's nodes.

## Decision

- **Kept from ADR-0377.** A `HardwareProfile` (`supervisor/src/apps/schemas.py`) has `id`, `soc` (a compatible of the host's device tree), `devices`, `requires` (those of the devices without which the container cannot use the hardware), `unmasked_paths` and `apparmor_unconfined`; `RK3588_VIDEO` of `supervisor/src/apps/catalog.py` is unchanged (`rockchip,rk3588`, the five nodes, `/dev/mpp_service` required, `/sys/firmware` unmasked, no AppArmor profile). `supervisor/src/apps/hardware.py` reads the host's `/proc/device-tree/compatible` with a `/bin/sh` that exits 3 where it does not exist, and on a host whose device tree names a profile's SoC looks for that profile's nodes with one `/bin/sh` loop of `[ -e ]`, both through `src/host.py` (ADR-0020) with a timeout of 15 s, in a worker thread (ADR-0021); a host without a device tree is not logged, any other failed read counts as a host without a device tree or without the nodes and is logged, and the app is installed as on every host. A profile applies on a host whose device tree names its SoC and that has every node of its `requires`; where one applies, the container gets those of its nodes that the host has as Docker devices `<path>:<path>:rwm`, Docker 29's masked paths without the profile's (`DOCKER_MASKED_PATHS`) and `apparmor=unconfined`, and keeps Docker's read-only paths, capabilities, seccomp profile and unprivileged mode; such a container is made through docker-py's low-level API with MaskedPaths added (`_create_container` of `supervisor/src/apps/router.py`). The container's root opens the nodes without a privileged mode, a group or a change on the host. The catalog API answers the profiles that apply on the host only, from the same reads per request in a worker thread, and the App Store shows **Hardware acceleration**, what the app gets and what to choose in it; the install's answer and the installed list name the host's nodes a container got, and the App Store warns, on the card and in the details, about a container that lacks a required node of a profile that applies, and that uninstalling and installing again gives it the hardware. UNOS chooses nothing inside an app (Jellyfin's RKMPP stays in its own `encoding.xml`, Immich's in its database).
- **Per container.** The main container's profiles are `AppTemplate.hardware` and a companion's are its own `Companion.hardware`. One `read_host_hardware(all_profiles(template))` per install or catalog request reads the host for the profiles of every container, and nothing when no container has one; `container_hardware(spec, host)` gives each container its devices, masks, security options and image. `for_host` keeps, for the main container and each companion, the profiles that apply on the host. An install that reads no hardware may still read the host for ADR-0381's port and space checks, which are no hardware reads.
- **A profile may choose the image.** `HardwareProfile.image`: where the profile applies, its container runs that image instead of its spec's, and `for_host` puts it in the template the catalog API answers, so the App Store shows what the install pulls. At most one profile of a container has an image, and that image is pinned (`PINNED_IMAGES`, ADR-0381); a shared profile constant carries none, and a template adds it with `model_copy`.
- **Required nodes inside a passed folder.** A `requires` path may lie under a passed device folder, such as a link in `/dev/dri/by-path`: the host's `[ -e ]` follows it, and the web UI's `hasHardware` (`webui/src/lib/api/apps.ts`) counts a required path as present when a device the container got equals it or is a folder that holds it (`device + "/"`). `missingHardware` checks the main container against `InstalledApp.devices` and each companion against its own `devices` in `InstalledApp.companions`.
- **The NPU.** `RK3588_NPU` of `supervisor/src/apps/catalog.py`: `id` `rk3588-npu`, `soc` `rockchip,rk3588`, `devices` `/dev/dri`, `requires` `/dev/dri/by-path/platform-fdab0000.npu-render` (the NPU's render node by its stable name, which the device check confirms; the card and render numbers follow the probe order), `unmasked_paths` `/sys/firmware` and `apparmor_unconfined`, no privileged mode. Immich's `machine-learning` companion gets it with the image `ghcr.io/immich-app/immich-machine-learning:v3.4.1-rknn`, and runs `immich-machine-learning:v3.4.1` where it does not apply, both pinned by digest. Under the mainline kernel, whose NPU driver (rocket, `/dev/accel`) has no such node, the profile does not apply.
- **Immich's server** gets `RK3588_VIDEO`, for RKMPP transcoding, which the user chooses in Immich (Administration, Settings, Video Transcoding, Hardware Acceleration: RKMPP).
- **The App Store's texts** for a profile and for what to choose in an app are keyed by profile and by app and profile: `rk3588-video` and `rk3588-npu`; `jellyfin:rk3588-video` and `immich:rk3588-video` (`webui/src/lib/components/apps/AppHardwareHint.svelte`).
- **Tests.** `TestHardwareOfTheSoc` of `supervisor/tests/test_apps.py` (as for ADR-0377) and tests per container: `container_hardware` with the image's swap and a folder's `requires`, one read of the device tree for all of an app's profiles, `for_host` with companions, the catalog API on a fake RK3588, a PC and an RK3588 without the NPU's link; the catalog's tests (each `requires` path equals a device or lies under a device folder, at most one profile with an image per container, profile images pinned); `webui/tests/apps-hardware.spec.ts` (`hasHardware` with `/dev/dri` covers the link) and `webui/tests/apps-stacks.spec.ts`. The device check reads with `scripts/dev/scenario.sh hardware` and proves the NPU by hand from the notes of `apps.rk3588-hardware-acceleration`: the RKNN models load and the NPU's cores show load (ADR-0018).

## Consequences

- Immich's machine learning container's root can use every node of `/dev/dri`, the display's card and render nodes too, not only the NPU's.
- On an RK3588 Immich's machine learning and its server, like Jellyfin, read the host's device tree and the rest of `/sys/firmware` (read-only) and run without AppArmor's `docker-default`; `/proc/sys` stays read-only to their root, which Immich's `systempaths=unconfined` would make writable.
- Off the RK3588, or without the NPU's node, the machine learning runs the CPU image with Docker's masks and AppArmor profile, and the App Store says which image it installs.
- The RKNPU driver's version is not checked by code; a model without an RKNN file runs on the CPU, which Immich logs.
- A path that a later Docker adds to its masks is not masked in a profile's container until `DOCKER_MASKED_PATHS` names it.
- Another SoC's NPU is one more profile with its own image, and its texts in the web UI.

## Considered options

- The NPU's link passed as a second device beside `/dev/dri`: it relies on how moby passes a link, which no check proved.
- Only the NPU's card and render nodes: their numbers follow the probe order, and the by-path name is a link.
- Immich's example as written, `systempaths=unconfined`: it also lifts the masks of `/proc` and makes `/proc/sys` writable (refused by ADR-0377).
- A second Immich template for the RK3588: two apps in the catalog for one, and the choice of image left to the user.
