# ADR-0391: An administrator binds SMB to chosen network interfaces by name, the loopback stays bound, and a change restarts smbd

## Context

smbd listens on every address of the host, and `hosts allow` of ADR-0095 refuses clients outside the LAN ranges; the ledger entry `shares.smb-bind-interfaces` asks that an administrator choose the interfaces that SMB listens on. Read from Samba 4.22's documentation and source (`smb.conf(5)`, `source3/smbd/server.c`, `source3/lib/interface.c`, `lib/socket/interfaces.c`): `interfaces` takes interface names or addresses and `bind interfaces only = yes` makes smbd bind the addresses of those interfaces, those that are up when it reads the list, except IPv6 link-local ones; an interface that is not broadcast-capable (a tunnel, WireGuard, PPP) is skipped, and so is a name that matches no interface, after a host name lookup of it; smbd opens its listening sockets only when it starts, a reload reads the list again but opens and closes no socket, and smbd refuses to start with no socket at all. The documentation warns that smbpasswd, in its default mode, connects to 127.0.0.1, which needs `127.0.0.1` bound. The owner delegated the decisions, asking above all that the feature be safe.

## Decision

- **Stored by name** in the new table `smb_bind_interfaces` (`SmbBindInterface` of `supervisor/src/shares/models.py`, one row per interface name; ADR-0319). No row is the default: SMB listens on every interface, as before, and smb.conf has neither line. Names, not addresses: DHCP and SLAAC change addresses, a name stays with its device. The database is in every backup, so a backup holds the choice and a restore brings it back; a backup made before the table restores with every interface.
- **Rendered** (`global_settings` in `supervisor/src/shares/smbconf.py`) right after `hosts allow`, only while rows exist: `interfaces = lo <the chosen names, sorted>` and `bind interfaces only = yes`. `lo` is always bound: smbpasswd's default mode, the `smbclient` and `smbpasswd -r` of `scripts/dev/scenario.py` and local tools reach smbd on 127.0.0.1, and smbd keeps a socket, and so starts, when no chosen interface is on the host. `hosts allow` stays as the first layer. An unchanged choice renders byte-identical text (ADR-0082).
- **Offered** by `GET /api/v1/shares/smb-interfaces` (`supervisor/src/shares/listen.py`): the host's interfaces as `ip -j addr show` reports them in the host's network namespace (through `src/host.py`), not the container's, each with its addresses, state and whether it has a LAN address (one that `hosts allow` admits, other than loopback and IPv6 link-local). Left out: the loopback (always bound) and the interfaces that System > Network hides, Docker's (`docker0`, `br-*`, `veth*`) and `dummy0` (`is_hidden` of `supervisor/src/network/links.py`). Listed but not offered: interfaces that are not broadcast-capable, which Samba skips. A chosen name that is not on the host is listed as missing.
- **Checked when stored** (`PUT /api/v1/shares/smb-interfaces`, `{"interfaces": [...]}`): at most 16 names, each of the Linux name rule of `INTERFACE_NAME_PATTERN` in `supervisor/src/security/validators.py` (so no Samba wildcard, list separator, quote, `/` or address literal), neither the loopback nor one that System > Network hides, none twice, none on the host that is not broadcast-capable. A choice must hold at least one interface that is on the host now, enabled, broadcast-capable and with a LAN address; any other choice is refused with 400, not warned about: it would leave SMB answering no computer of the LAN. Names not on the host now are kept (an unplugged USB adapter). The empty list, back to every interface, is always accepted; another choice is refused with 503 while the host's interfaces cannot be read.
- **Checked when rendered** (ADR-0144): every row again. A row that breaks the name rule, or names the loopback or a hidden interface, is left out with a problem of `GET /shares/smb-status`; when rows exist and none is valid, smb.conf binds the loopback alone, so that SMB answers only the NAS itself, never every interface. The serializer guard `_safe_interface` refuses an invalid name. While rows exist, `GET /shares/smb-status` also names a choice of which no interface is on the host with a LAN address (a restore from other hardware, an adapter unplugged).
- **A change restarts smbd.** An apply whose `interfaces` or `bind interfaces only` line differs from the installed file's (`smbconf.listen_lines`) runs, after testparm and the atomic install (ADR-0089) and in place of the reload, `systemctl reset-failed smbd` and then `timeout 60 systemctl restart smbd` (`smb._restart_smbd`, under the host's timeout as ADR-0258 asks): every open SMB connection ends. This holds for a change on the Shares page, a restore and the startup reconcile. The Shares page says so before it saves, with the number of open sessions. After a restart no reload and no close of a share is pending, since no connection outlives it. A failed restart is a warning of the answer, a problem of `GET /shares/smb-status` and an audit entry that did not succeed, and the Shares page offers Restart SMB, until Restart SMB or the next change of the interfaces succeeds. No other apply tries it again: a user's password change would then end every session. That state lives in memory, so after a restart of the supervisor only the comparison of smbd's listeners below names it.
- **What smbd binds later.** smbd binds the addresses that the chosen interfaces have when it starts. An address that comes later (a new DHCP lease, IPv6 addresses after the start, a USB adapter plugged in, an interface enabled again) gets no socket until smbd restarts. `GET /shares/smb-interfaces` compares smbd's TCP 445 listeners (`ss -H -l -n -t -p`) with the choice: each LAN address of a chosen interface without a listener, each listener outside the choice (every address included), and no listener at all are problems with `restart_needed`, and the Shares page then offers Restart SMB (`POST /api/v1/shares/smb-interfaces/restart`), which asks first. UNOS never restarts smbd for this by itself. A renamed interface is another interface: its old name stays chosen and is listed as missing until the administrator chooses the new one.
- **Discovery does not follow the choice.** wsdd2 and avahi-daemon keep answering on every interface over IPv4 (ADR-0275), and smbd registers `_smb._tcp` with avahi-daemon for every interface (`AVAHI_IF_UNSPEC` in `source3/smbd/avahi_register.c`).
- **Audit and roles.** The shares router is administrator-only (ADR-0030). A change writes `smb_interfaces_changed` and Restart SMB `smb_restarted` (resource type `smb`, severity warning: sessions end); a PUT that changes nothing writes nothing (ADR-0320).
- Tests: `supervisor/tests/test_smb_interfaces.py` (the rendering, the API with a fake host whose smbd binds as Samba does, how `ss` writes listeners, the restart and its failure, the status, a restored database and a backup's table), `supervisor/tests/test_smbconf_testparm.py` (both lines through the real testparm), and `webui/tests/smb-interfaces.spec.ts` and `webui/tests/mobile-layout.spec.ts` on route fakes (the stand-in has no host network).

## Consequences

- SMB stops answering on the addresses of interfaces that are not chosen: a second network card, Wi-Fi, a VPN or tunnel interface. Docker's bridges are not chosen, but a container still reaches SMB at the host's LAN address: Linux accepts a packet for a local address on any interface.
- Every change of the choice ends the open SMB connections; clients reconnect, and a copy in progress fails.
- An address that changes while smbd runs leaves SMB unreachable there until Restart SMB; the Shares page names it, and `docs/USER_GUIDE.md` advises a fixed address (a DHCP reservation) for the NAS. After a reboot, smbd binds what the chosen interfaces have when Samba's unit starts it, after `network-online.target`; the device check reads it.
- A computer on the network of an interface that is not chosen can still list the NAS through WS-Discovery or Bonjour and then fail to connect.
- smbd asks the host's resolver for a chosen name that is not on the host when it reads the list, as it reads any entry that is not an interface; should the name resolve to an address of the host, smbd binds that address too. Only an administrator, or a restored database, chooses such a name, and `hosts allow` still applies.

## Considered options

- `"<name>;options=dynamic"` (Samba 4.21 and later), with which smbd opens and closes sockets as addresses of the interfaces it knew at its start come and go: not used. smbd opens a new listening socket at every notification of an added address without looking for one it has, and its sockets take `SO_REUSEPORT`, so the bind succeeds; Linux sends that notification again whenever an address's lifetime is renewed (router advertisements, DHCP renewals). It also covers no interface that was missing at the start.
- Binding by address: addresses change; a name keeps its meaning.
- A typed confirmation for a choice without a LAN interface: such a choice has no use, so it is refused.
- Restarting smbd by itself when its listeners drift from the choice: a restart ends every session, so it waits for an administrator.
- Leaving the loopback out: smbpasswd's default mode and the scenario checks need 127.0.0.1, and smbd would not start while no chosen interface is on the host.
- wsdd2 and avahi-daemon following the choice: their settings are `deploy/install.sh`'s, which rewrites them at every run, wsdd2 takes a single interface (`-i`), and their announcements give no access.
