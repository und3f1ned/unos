# ADR-0085: The original smb.conf is kept once as smb.conf.unos-import-backup

## Context

The one-time import (ADR-0084) turns a file that UNOS did not write into rows, and the next apply replaces that file with UNOS's rendering. The import only narrows access and drops options UNOS does not support (ADR-0086), so the original file is the only complete record of what the host served before, and the uninstall text points to it.

## Decision

- Whenever UNOS reads a live smb.conf for the import and the file does not start with UNOS's header (`smbconf.HEADER`, `# Generated by UNOS from its database. ...`), it first copies the original bytes to `<smb.conf>.unos-import-backup` (`keep_import_backup` in `supervisor/src/shares/smb.py`): a temporary file, fsync, rename and an fsync of the directory.
- An existing copy is never overwritten, so it keeps the first original even when later triggers see other foreign files.
- The order is: copy, commit of the import, apply. A copy that cannot be written fails the import, and smb.conf stays untouched.
- `deploy/install.sh` keeps the host's earlier file as `smb.conf.original` and writes the file that UNOS generates, so the import backup is written only when the import finds a file that UNOS did not write, for example after a manual installation; `docs/INSTALL.md` says so.
- Tests: `supervisor/tests/test_share_import.py` (`TestCopy`).

## Consequences

- The file from before UNOS's rendering can be checked or copied back by hand. Copying it back brings back whatever access it gave, so the uninstall text tells to check it first (ADR-0180).
- Only one import backup is kept; keeping several is the `feature-list.json` entry `shares.keep-every-replaced-copy`.
