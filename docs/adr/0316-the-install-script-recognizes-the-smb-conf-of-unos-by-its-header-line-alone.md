# ADR-0316: The install script recognizes the smb.conf of UNOS by its header line alone

## Context

`configure_samba` of `deploy/install.sh` kept an existing `/etc/samba/smb.conf` that had the
line `server string = UNOS NAS` anywhere, for installations of releases that had not imported
their shares into the database yet: their shares existed only in that file. UNOS has no such
installations (ADR-0207), and every smb.conf that the supervisor writes starts with its header
(`HEADER` of `supervisor/src/shares/smbconf.py`, ADR-0074). The ledger entry
`deploy.no-legacy-smb-conf-recognition` asks for the header line alone; the agent took it up
under the owner's delegation ("work on through the features, ask no questions; I allow
everything", in translation, 2026-11-09).

## Decision

- `configure_samba` keeps an existing `/etc/samba/smb.conf` only when its first line starts with
  `# Generated by UNOS from its database.`, the beginning of `HEADER`, and then only starts Samba.
- Any other file, one that only has `server string = UNOS NAS` or has the header line below its
  first line included, is handled like any other smb.conf of the host: kept as
  `smb.conf.original` when there is none yet, and replaced by the file of `render_config([])`.
- `server string = UNOS NAS` stays in the `[global]` that ADR-0281 pins, but marks no file of
  UNOS: the remark of ADR-0281 that `install.sh` recognizes a file by it no longer holds.
- Tests: `TestInstallScript` of `supervisor/tests/test_deploy_scripts.py`,
  `test_rerun_keeps_a_file_that_starts_with_the_unos_header_line`,
  `test_a_file_that_does_not_start_with_the_header_line_is_replaced` and
  `test_rerun_keeps_the_smb_conf_that_unos_generated`.

## Consequences

- A smb.conf written by hand with UNOS's server string is moved aside on a run of `install.sh`;
  when `smb.conf.original` exists already, it is replaced without a copy, as any other file of
  the host is.
