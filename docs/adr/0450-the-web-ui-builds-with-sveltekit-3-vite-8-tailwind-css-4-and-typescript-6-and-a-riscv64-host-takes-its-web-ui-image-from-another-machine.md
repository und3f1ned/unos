# ADR-0450: The web UI builds with SvelteKit 3, Vite 8, Tailwind CSS 4 and TypeScript 6, keeps its look, and a riscv64 or ARMv7 host takes its web UI image from another machine

## Context

ADR-0427 moved the web UI to Svelte 5 on SvelteKit 2 and left the other new majors of its toolchain
to the feature-list entry `webui.toolchain-major-versions`: SvelteKit 3, @sveltejs/vite-plugin-svelte
7, Vite 8, Tailwind CSS 4, TypeScript, @sveltejs/adapter-static 4 and lucide-svelte 1. Dependabot's
group of all of them failed `npm ci` (ADR-0231). The entry asks for the current majors, `npm ci`
without `--force`, an unchanged look and no change of behaviour. Vite 8 bundles with Rolldown and
minifies with Lightning CSS, which Tailwind CSS 4 uses too: native binaries, published for neither
linux/riscv64 nor linux/arm with musl (the libc of the web UI's Alpine builder), where `install.sh`
and `update.sh` built the web UI's image (ADR-0373: on a SpacemiT K1 it came from another machine
already). The owner delegated the decisions of this entry, above all safe.

## Decision

- Exact versions in `webui/package.json`, `webui/package-lock.json` regenerated by npm from the
  previous lock: @sveltejs/kit 3.2.0, @sveltejs/vite-plugin-svelte 7.3.1, vite 8.3.8, tailwindcss
  4.3.5 with @tailwindcss/vite 4.3.5 (its Vite plugin, in place of postcss and autoprefixer, which
  leave `package.json`), typescript 6.0.3, svelte-check 4.7.8 (the current release), and
  @sveltejs/adapter-static 4.0.1; lucide-svelte 1.0.1 in `dependencies`. Each release and every
  package the lock adds is at least a week old, as Dependabot's cooldown and ADR-0449 keep them:
  SvelteKit 3.2.1 to 3.4.0 and @tybys/wasm-util 0.10.5 (wasm32 only) were younger, so the lock
  holds 3.2.0 and 0.10.4. `engines` stays `>=22`, the builder's major version
  (`TestContinuousIntegration`): SvelteKit 3 wants 22.17, which Alpine 3.22 (22.23) and CI's
  latest 22 exceed.
- TypeScript stays at 6: TypeScript 7.0.2 is the current major, but SvelteKit 3 accepts `^6.0.0`,
  svelte-check 4.7.8 `^5.0.0 || ^6.0.0` and typescript-eslint 8.72 `<6.1.0`. The entry stays open
  for TypeScript 7, the move from lucide-svelte, deprecated, to @lucide/svelte (a new dependency, the
  owner's call), and from `$lib` to SvelteKit 3's `#lib`.
- SvelteKit 3 refuses `svelte.config.js`: its options are those of `sveltekit({...})` in
  `webui/vite.config.ts` (the adapter, the CSP, `preprocess`, and `dynamicCompileOptions`, the
  exported `compileOptions` that compiles `src/` in runes mode, ADR-0427). `$lib` stays an `alias`
  there, which SvelteKit 3 deprecates and warns about in each build. `$app/environment` becomes
  `$app/env`; `goto`'s deprecated `replaceState` becomes `replace`, and `noScroll` with
  `keepFocus` becomes `reset: false`: SvelteKit 3 dropped them (outside development it ignores
  them), and a tab change of System or Account would have scrolled to the top and dropped the
  focus. `webui/tsconfig.json` extends `$app/tsconfig` and names `src`, `tests` and
  `vite.config.ts`, which SvelteKit 2's generated configuration included. Where ADR-0427 and
  ADR-0449 name `svelte.config.js`, it is now `vite.config.ts`.
- Tailwind CSS 4 without `tailwind.config.js` and `postcss.config.js`: `webui/src/app.css` imports
  its theme and preflight, and holds the tokens in `@theme` blocks; where ADR-0400, ADR-0405 and
  ADR-0438 name `tailwind.config.js`, it is now these blocks. The colour tokens are
  `@theme inline reference`, each `--color-<name>: rgb(var(--color-<name>))` (with its own opacity
  for surface-muted and border-muted): a utility writes the value, and Tailwind declares no variable
  of its own over the theme's channels of ADR-0405. The fonts, `text-2xs`, the radii, the shadows
  and `animate-spin-slow` keep their values; the breakpoints keep theirs in px (4's are in rem,
  which move with the browser's font size). The ring's default is brand-ring, 3 px, as the old
  configuration named it (its default never applied there; no element uses a ring without a
  colour). `scripts/design-check.mjs` and `supervisor/tests/test_webui_theme.py` read the tokens
  there.
- What Tailwind CSS 4 changed is put back, so that the pages look and move as before: the line
  heights of the text sizes in rem (4's ratios gave a 13 px text in a 14 px row 18.6 px, not 20 px);
  `hover:` on every device (`@custom-variant`); `outline-none` is `outline-hidden`; the utilities
  sit in the layer `components`, after the classes of `app.css`, so that a utility wins over a
  class of the same specificity and a more specific class (`.table-stack tr`) over a utility
  (`table-row`), as in Tailwind CSS 3 (in a layer of their own every utility would win). A
  component's `<style>` stays outside the layers, so it wins over every layer: its scoped rules
  (two classes or more) won in Tailwind CSS 3 too, and no element they style takes a variant of
  three (`group-*`, `peer-*`); a layer that a component's style sheet named would set the order
  of the layers, since the browser can load it before `app.css` (`ui.css` comes first); `space-y-*`,
  `divide-y` and `divide-*` put the space or line before every child but the first, over the
  child's own (custom utilities of `app.css` that leave Tailwind CSS 4's own rule for the class
  with nothing to do); `scrollbar-thin` is a custom utility, so that `@apply` reaches it. In the
  base layer, what 3's preflight gave or left to the browser and 4's resets: a border without a
  colour takes the token `border`, a button the pointer, a table cell its 1 px padding, an option
  its padding, a field its background and corners, a field or a button its own figures and font
  style (4 makes them inherit), a search field is drawn as a text field, and a date or time field
  keeps the browser's parts. `translate-x-*` and `rotate-*` set `translate` and `rotate`, not
  `transform`: the switch's knob, Select's chevron and the phone drawer transition those. The six
  `transition-colors` are the list of Tailwind CSS 3, without `outline-color`, which would fade a
  focus ring in from the text's colour. A class of `app.css` is no longer applied with `@apply`
  (`card`, `scrim`, `tabular` are written out), and a component's `<style>` with `@apply` starts
  with `@reference` to `app.css`.
- Two rules of `app.css` apply now that never did: Tailwind CSS 3 dropped a component's rule whose
  class no file names whole, and `ToastRegion` names `toast-<tone>`, `Input` `field-w-<width>` at
  run time. A toast's left edge takes its tone's colour, as its icon did (ADR-0432), and a field
  of `width` xs, sm or md is 8.5, 12 or 20 rem wide (the interval of System > Updates' automatic
  install), as `Input` and `webui/AGENTS.md` say. `tests/design-foundations.spec.ts` and
  `tests/updates.spec.ts` check both.
- A colour with an opacity (`bg-brand/20`) is a `color-mix()` in oklab, which the browser reports
  as `oklab(...)`: the same colour. `webui/tests/theme.spec.ts` converts it back, and reads the
  rules inside `app.css`'s layers.
- lucide-svelte 1 dropped the brands' logos: Slack's channel takes `Hash` and an app's GitHub link
  `Code`. Its other icons are redrawn in places, and an icon without an `aria-*`, `role` or
  `title` prop gets `aria-hidden="true"`. Its components are still Svelte 4's, compiled in legacy
  mode as a library's (ADR-0427).
- The builder stage of `webui/Dockerfile` runs on the platform that builds
  (`FROM --platform=$BUILDPLATFORM`, which needs BuildKit, as `docker compose` and `docker buildx`
  use it): the static files are the same on every platform, so `docker buildx build --platform
  linux/riscv64 ... webui` builds them natively and only Caddy's stage is riscv64's. On every
  riscv64 host and every 32-bit ARM host (`uname -m` riscv64 or armv7l,
  `webui_elsewhere_platform`), not only a SpacemiT K1, `deploy/install.sh` builds only the
  supervisor and starts the web UI from `deploy-webui:latest`, and without that image stops
  before it builds anything and says how to make it for that platform and load it;
  `deploy/update.sh` builds only the supervisor, says so, and after a rollback asks to load the
  image of the new version again. Kept from ADR-0373: the dev device's way (ADR-0184), the static
  files built off the device and only the image's final stage on it, makes the same image.
- Tests: `test_webui_theme.py`, `test_webui_design_system.py`
  (`test_the_table_names_only_tokens_of_the_theme`), `test_webui_runes.py`
  (`test_the_vite_config_compiles_the_web_ui_in_runes_mode`), and in `test_deploy_scripts.py`
  `TestContinuousIntegration`, `TestUpdateScript` and `TestInstallScript` (the riscv64 and armv7
  tests).

## Consequences

- Checked before the commit, on the stand-in, against the previous build: screenshots of
  Dashboard, Storage, Shares, Users, System > General, System > Updates, Account and sign-in at
  1440 and 375 px in both themes are the same size and differ only in the icons that lucide redrew
  (77 to 712 pixels a page), in one level of 255 at some rounded corners, and in the Dashboard's
  live figures; the computed styles and boxes of every element of 25 pages at both widths and in
  both themes differ only in how the same values are written (oklab, `translate`, the parts of
  `box-shadow`), in the transitions named above, and in boxes that hold live figures or a path of
  the stand-in. Bare elements under both style sheets differ only in a file field's button and
  `<dialog>`, which the web UI does not show, and in the placeholder of a field without a
  `form-*` class, which the design check refuses. States that a static page does not show (hover,
  focus, an open menu or dialog) have no screenshots: the full E2E run covers them, and the only
  classes that the new style sheet has and the old one lacked are those named here and four that
  no element takes.
- The web interface needs a browser of 2023 or later: Chrome or Edge 111, Firefox 128, Safari 16.4
  (iOS 16.4), for Tailwind CSS 4's cascade layers, `@property`, `color-mix()` and range media
  queries, and Vite 8's default target (README.md, `docs/INSTALL.md`). Before, Safari 14 drew it.
- `webui/node_modules` grows from 154 to 185 MiB (lucide-svelte 1 alone is 30 MiB); the web UI
  image's npm layer is rebuilt once.
- A riscv64 host other than a K1, and an ARMv7 host, can no longer install or update UNOS alone:
  another machine with Docker builds its web UI image for each version, until release images
  (`deploy.riscv64-release-images`). Rolldown and Lightning CSS for those platforms would bring the
  build back to the host. A Docker that builds without BuildKit (`DOCKER_BUILDKIT=0`) refuses the
  web UI's Dockerfile.
- `space-y-*` relies on Tailwind CSS 4's own rule computing its margin with
  `--tw-space-y-reverse`, and `divide-y` on its rule drawing no top line on the first child: if a
  later Tailwind CSS changes them, children get the space or the line after them as well, which
  the screenshots of the next toolchain move would show. A `space-y-px`, an arbitrary or negative
  `space-y-*`, a new `transition-colors` and `outline-none` get Tailwind CSS 4's behaviour; none
  is used.
- The old names that Tailwind CSS 4 still takes (`shadow`, `rounded`, `flex-shrink-0`) keep Tailwind
  CSS 3's values here.
